# Hutashana CRM implementation plan

> **For agentic workers:** Use superpowers:executing-plans. User requested immediate implementation; execute inline without further planning approvals.

**Goal:** Build a functioning kitchen-business CRM with an isolated demo and authenticated Supabase deployment path.
**Architecture:** Next.js modular application; pure validated domain commands; server-only Supabase repository; transactional optimistic concurrency, immutable issued documents, outbox jobs. No external send occurs from demo mode.
**Tech Stack:** TypeScript, Next.js, React, PostgreSQL/Supabase, Decimal.js, Zod, React PDF, Vitest, Playwright.
**Spec:** `docs/reference/PRD.md`, `DESIGN.md`, `IMPLEMENTATION.md`; current user authorizes implementation and delegates routine choices.

## Global constraints
- INR; Asia/Kolkata business dates; fictional data clearly marked; no production rates or tax defaults invented.
- Organization and role checks on server; no service key in browser; private documents.
- Published quotes and issued invoices immutable; financial corrections append history.
- No automatic external communication without explicit configured templates, consent, and enabled policy.
- Vercel Hobby excludes commercial deployment. Deployment is not performed in this build.

## Review focus
- Decimal conversion, per-line tax and discounts must reconcile to paise.
- Concurrent invoice numbering and receipts must not overwrite another user's work.
- Supplied organization/role, imported notes, and callback payloads cannot grant access.
- Paid, opted-out, or disputed recipients must not receive collection automation.
- Refresh, download, mobile navigation, malformed imports and empty collections must remain usable.

## Decisions / ledger
- Work in the user's empty dedicated repository on `codex/crm-implementation`; there is no existing product checkout to isolate.
- User's instruction to start building opts out of further brainstorming/approval gates.
- Use generic organization-scoped operational records with validated discriminated schemas; financial transitions are controlled domain commands. Database writes are one transaction with an organization revision comparison to prevent lost updates. Intended initial scale: one business, up to 10,000 active records; archive/reporting pagination is a subsequent scale boundary.
- Default taxes are zero/unconfigured and invoice issue requires billing identity and tax-review acknowledgement. Real rates must be imported.
